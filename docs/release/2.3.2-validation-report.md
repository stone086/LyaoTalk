# LiaoT 2.3.2 Validation Report

Version: 2.3.2
Release name: staging-evidence-kit

## Purpose

2.3.2 turns the remaining roadmap gaps into executable evidence workflows. It does not pretend that real external tests have been run; it adds the scripts, templates, configs, and release gates needed to run them on staging and record results.

## Added

- Evidence index and per-stage evidence result files under `docs/evidence/`.
- `scripts/staging_evidence_collect.sh` to gather staging evidence outputs.
- `scripts/evidence_gate_validate.sh` to ensure evidence materials are present.
- `scripts/performance_baseline_run.sh` for k6 baseline execution.
- `scripts/backup_restore_drill.sh` for non-destructive drill recording.
- `scripts/regenerate_python_hashes.sh` for target-platform hash regeneration.
- Prometheus and Alertmanager example configs and docker compose file.

## Local validation commands

```bash
bash scripts/evidence_gate_validate.sh --local
bash -n scripts/staging_evidence_collect.sh
```

## Additional lockfile cleanup

`apps/web/package-lock.json` was normalized so `resolved` tarball URLs no longer point to the transient internal build registry. This avoids reproducible-build failures on machines that use the public npm registry or a different mirror.

## Local npm limitation

A fresh `npm ci` was attempted after lockfile normalization, but this sandbox forces a protected internal npm registry and the internal mirror did not contain `why-is-node-running@2.3.1`. Therefore the final npm build gate must be rerun on staging/CI with a working registry. Previous 2.3.1 had already passed frontend build/test; 2.3.2 changes are documentation/scripts/config only plus lockfile URL normalization.
