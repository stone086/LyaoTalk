# LiaoT 1.8.1 Validation Report

Package: `liaot-1.8.1-hash-pinned-python.zip`

## Summary

1.8.1 upgrades the 1.8.0 trusted-build line by replacing the API runtime dependency file with a hash-pinned `requirements.txt` and requiring hash verification during installs.

## Changes verified

- Project version bumped to 1.8.1.
- `apps/api/requirements.in` remains the human-edited input.
- `apps/api/requirements.txt` contains SHA-256 hashes for all resolved runtime packages.
- `install.sh` uses `pip install --require-hashes -r requirements.txt`.
- `manage.sh` uses `pip install --require-hashes -r requirements.txt`.
- CI installs API dependencies with `--require-hashes`.
- `pywebpush` was bumped from 2.0.0 to 2.0.3 to support the trusted-build wheel-based resolution path.

## Local validation performed

- `pip install --require-hashes -r apps/api/requirements.txt` was tested in a fresh virtual environment in the release environment.
- `bash scripts/trusted_build_validate.sh --local` passed.
- `bash scripts/stage0_validate.sh --local` passed.
- `bash scripts/omemo_runtime_validate.sh` passed.
- `bash -n install.sh`, `bash -n manage.sh`, `bash -n uninstall.sh` passed.
- `python3 -m compileall -q apps/api/app apps/api/alembic` passed.
- `npm ci`, `npm run build`, `npm test`, and production high-level `npm audit` passed.

## Limitations

The generated Python hash lock was validated with CPython 3.13 on Linux x86_64. If deployment uses CPython 3.11/3.12, regenerate `requirements.txt` from `requirements.in` on a matching trusted build host before production promotion.
